# RCA — Google Drive linking not working on https://qalamok.com

## Problem statement
Admin clicks "Connect Google Drive" in /settings → `/api/drive/connect`. Drive is only enabled when `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET` are set; otherwise `/api/drive/status` returns `configured=false`. User added these vars to the preview `backend/.env` AFTER the last deploy and asked whether production has them, whether prod logs show errors, and whether the computed redirect_uri is correct.

## Deployment
- deployment: marhaba-preview-4 (339cb29c-d435-431f-aef9-34290eafaf14)
- active run: d2558e31-cb4e-42f4-8aef-f62c60f2f530 (redeploy, trigger=secret_change, completed 2026-10-19 02:32 UTC)
- frontend_type: kubernetes; custom domains qalamok.com + www.qalamok.com both verified & DNS-linked
- live URL: https://marhaba-preview-4.emergent.host

## Findings (evidence)

### 1. Production is MISSING the Google env vars — CONFIRMED (primary prod issue)
`list_secrets` on the active run d2558e31 returns these keys only:
APP_TZ, APP_URL, CORS_ORIGINS, DB_NAME, EMAIL_FROM_NAME, EMERGENT_EMAIL_KEY, EMERGENT_LLM_KEY, INTEGRATION_PROXY_URL, MONGO_URL, REACT_APP_BACKEND_URL, WEBHOOK_CRON_SECRET.
**Neither `GOOGLE_CLIENT_ID` nor `GOOGLE_CLIENT_SECRET` is present** (metadata_available=true, so this is a reliable read). The expected client id `428549129934-...apps.googleusercontent.com` could not match because the key does not exist.

Why: the active run (02:28–02:32) was triggered by a secret_change BEFORE these two keys were added to the preview `.env`. Custom keys new in the preview `.env` are only seeded into production on the NEXT deploy. So production still runs without them → `/api/drive/status` returns `configured=false` → Drive is disabled in prod.

### 2. Production backend logs — CONFIRMED, consistent with "not configured"
`fetch_app_logs` (run d2558e31, 1440m, filter drive|callback|oauth|GOOGLE):
- `GET /api/drive/status` → repeatedly `200 OK` (serving, returning configured=false; no 5xx)
- `GET /api/drive/connect HTTP/1.1" 401 Unauthorized`
- `GET /api/drive/status HTTP/1.1" 401 Unauthorized` (unauthenticated callers)
No `/api/drive/callback` hits and no stack traces. Backend is healthy; there is no server error — the flow simply never reaches callback because Drive is not configured. (connect also gates on an admin session → 401 for non-admin callers.)

### 3. redirect_uri / forwarded headers — could NOT be fully verified in prod
Because Drive is `configured=false` in production, `/api/drive/connect` never builds the authorization_url, so there is no prod log line showing the computed redirect_uri. However: qalamok.com is verified and DNS-linked, SSL active, and the k8s nginx frontend terminates/forwards the standard `x-forwarded-proto: https` / `x-forwarded-host: qalamok.com`. So once the vars are present, the computed redirect_uri will be `https://qalamok.com/api/drive/callback` as intended. This is INFERRED, not observed.

### 4. Google redirect_uri_mismatch (Error 400) — user-side Google Cloud config
Already established by the reporter and NOT a production platform issue: `https://qalamok.com/api/drive/callback` (and the preview callback) are not registered as Authorized redirect URIs on the Google OAuth client. This remains true independent of the prod env fix.

## Root cause
Two independent issues, both outside the deployment platform:
1. Production is missing `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (added to preview `.env` only after the last deploy) → Drive reports not-configured in prod → a redeploy / secret add is required.
2. Even once configured, Google returns 400 redirect_uri_mismatch because the callback URIs are not registered on the user's Google Cloud OAuth client.

No production source bug, no 5xx, no infra fault found.

## Suggested fixes
- USER (Secrets + Redeploy): Add `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in Deployment Panel → Secrets (values from preview `backend/.env`), then redeploy so production picks them up. (A plain redeploy will also seed them from the preview `.env` as new keys.)
- USER (Google Cloud): In the Google Cloud Console OAuth client, add Authorized redirect URIs `https://qalamok.com/api/drive/callback` (and `https://www.qalamok.com/api/drive/callback` if www is used) to clear the Error 400 redirect_uri_mismatch.
